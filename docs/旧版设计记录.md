```powershell

Copy-Item .env.example .env
```

后台显示题目分布、用时、未展示/展示未答、修改历史、完整会话和权重版本。

自动校准根据同一变量两道行为题的配对一致性，达到样本门槛后更新变量证据权重；已开始的测验固定使用原版本。

一個網頁測驗工具。這個 repo 正在從 **1.0 的「完整屬性面板」** 轉向 **2.0 的「強項查找器」**，

# 2.0（現在在做的）

## 理念

> **找出一件你自己平時可能沒察覺到的、擅長的事。**

關鍵字是**沒察覺到**。如果你已經知道自己邏輯好，再告訴你一次等於沒說——
產品的價值全在「意外」上。這一句話把整個機制翻了過來：

```
1.0：輸出 = argmax(能力分)
2.0：輸出 = 你不知道的那個 argmax
```

## 惊喜從哪來：結構性的，不是靠對比自評

最直覺的做法是分兩條軌——問你覺得自己怎麼樣（自評），再用行為題測實際表現（證據），
取差值最大的。但這樣做有兩個問題：自評題會虛高，而且會污染後面的行為題。

所以 2.0 **不設自評軌**。惊喜是結構性的：

- 你從頭到尾**只回答具體的事**（「陌生城市不靠導航走得回去嗎」），
- 你**沒看過**那 25 個候選的清單，
- 你**沒給自己打過任何分**，
- 系統在暗處把 25 個候選一路篩到剩一個。

最後告訴你「你空間能力很強」之所以意外，是因為**你從來不用這種範疇想自己**。
歸類這件事是產品替你做的。

## 唯一的自評：最後一題

但「已知強項 vs 盲點」還是需要知道你以為自己強在哪。解法是把自評壓縮成**最後一道題**：

> 「以上這些問題，你覺得測出來你最強的會是哪一個？」（這時才把 25 個候選攤開）

放在最後 → **零污染**，不可能影響前面任何一題。然後：

| 情況 | 輸出 |
|---|---|
| 猜中 | 「你沒有明顯盲點——自我認識準確本身就很少見」+ 證據 |
| 猜錯，但那個也成立 | 「你知道的：X。**你可能不知道的：Y**」 |
| 猜錯，證據不支持 | 只給盲點，對猜的那個輕輕帶過，不打臉 |

## 計分：純減法

每個葉子起手 **10 分**。定向題按答案扣分，**跑分 ≤ 3 就出局**，之後不再出它的題。

| 答案檔 | A 最弱 | B | C 中間 | D | E 最強 |
|---|---|---|---|---|---|
| 增減 | −7 | −5 | −3 | −1 | +1 |

為什麼是減法而不是加法——這是自適應測驗的關鍵：

> 大部分葉子只會被問到 0–2 題。**加分制下「沒問到」= 0 分 = 看起來像弱項**；
> 減分制下「沒問到」= 留在基準 = 中性，只有真的答出弱點才往下扣。

排名用**平均**而非累計，因為不同葉子的題數不一樣。

## 流程（~30–35 題，自適應）

| 階段 | 題數 | 機制 |
|---|---|---|
| A 廣譜剔除 | 10 | 每題擺 5 件不同葉子的具體事，問「哪件最吃力」。被選中的直接出局。每個葉子在這 10 題裡出現恰好 2 次 |
| B 定向驗證 | ~16 | 倖存者逐個上近客觀行為題，答弱就出局 |
| C 重點確認 | ~5 | 最後領先的幾個補第二題，湊足證據 |
| D 預測 | 1 | 見上 |

**階段 B 不設題數上限**——每個倖存的葉子都必須被問到一次。
（初版設了 14 題的上限，實測時真正最強的那個葉子因為排在預算之後而被靜默跳過，
整個產品的意義就沒了。這是自適應搜尋最容易犯的錯。）

## 25 個候選

5 個根 → 分支 → 葉。設計約束是**每個葉盡量互斥**（延續 1.0 guide 的「不可組合還原」原則）。

```
體魄     力量爆發 · 速度耐力 · 平衡協調 · 柔韌精細 · 身體底子
決策     開放度 · 決斷速度 · 跟進紀律 · 抗沉沒成本
認知馬力 學習力 · 記憶力 · 語言能力 · 邏輯推理 · 空間能力 · 數感 · 創造力
心性     穩定性 · 耐挫恢復 · 自我認知 · 社交敏感 · 共情深度 · 表達力 · 領導組織
產出     視覺審美 · 音律感
```

從 1.0 的 43 個扁平維度收斂而來。過程中砍掉／合併的：外形氣場、幽默感（併入表達力）、
反應速度＋手眼協調（併入平衡協調）、意志力＋專注力＋時間統籌（併成跟進紀律）、
學習力與記憶力則反過來從各領域裡抽出來獨立成葉。

**「決策」這個根差點沒活下來**：嚴格 MECE 之下它像是認知×心性的衍生量
（就像 guide 說「運動能力 = 力量+速度+平衡的衍生值，不獨立成維度」）。
最後保留的理由是給它劃了專屬領地——只收決策特有的部分（風險姿態、決斷速度、
跟進紀律、抗沉沒成本），通用認知歸認知馬力、情緒歸心性。

## 打開

[`v2.html`](v2.html) 是一支完全靜態的單檔網站，**雙擊就能開**，不需要伺服器、沒有建置步驟。
答案存在 `localStorage`，可中斷續做。鍵盤 1–5 或 A–E 可快速作答。

## 已知的坑

1. **剪枝錯誤會滾雪球**——階段 A 把一個真正的強項誤判出局，後面救不回來。
   目前只靠「每個葉子在階段 A 出現兩次」來降低誤殺率，沒有回查機制。
2. **只出一個答案 = 全押一注**。錯了就像算命失手。所以結果頁必須**引用受測者自己的回答**
   當證據——這是它和星座唯一的區別。
3. **題庫是初版**。目前 10 道廣譜題 + 50 道定向題（每葉 2 道）是為了讓引擎跑起來寫的，
   還沒有經過 1.0 那套「零經驗門檻 / 無最優解 / 交叉驗證」的檢驗。**正在重新設計中。**

# 後台

[`server/`](server/)：Node + Express + SQLite（Node 22.5+ 內建的 `node:sqlite`，免原生編譯）。

```bash
cd server
npm install
cp .env.example .env   # 填上 ADMIN_PASSWORD
npm run import
npm run dev            # 後台 http://localhost:4000/admin
```

- `npm run import` 把 `index.html` 的題庫解析進資料庫——不複製文字，改完題重跑即可。
- 網頁介面編輯既有題目的內容。
- **題庫體檢**：不需作答資料的靜態指標。查出 1.0 的區塊三有 **28/58 題存在 Pareto 支配選項**
  （所有選項踩同一組維度、數值變成一條排序，等於有標準答案，違反該區塊的設計前提），
  以及 5 個硬件維度沒有交叉校驗題。

細節見 [server/README.md](server/README.md)、判讀方式見 [docs/準確率方法論.md](docs/準確率方法論.md)。

> ⚠️ 後台整套是圍繞 1.0 的四區塊結構建的。2.0 沒有「區塊三」也沒有「交叉校驗區塊」，
> 所以 `audit.js` 裡的稽核概念有一半會失效，之後要跟著重做。
