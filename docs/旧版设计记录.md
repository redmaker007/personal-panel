# 旧版设计记录（归档）

这里记录 **2026-09-06 之前** 的设计与实现，全部已被取代。当前状态见仓库根目录
`README.md`、[新版升级说明](新版升级说明.md) 与 [sf2.2 题库改版说明](题库改版说明.md)。

保留这份记录，是为了说明**为什么会改成现在这样**——避免以后又走回同一条路。

## 第一版：单文件原型（`v2.html`，约 700 行）

- 纯静态、无服务器、双击即开，答案只存 `localStorage`。
- **阶段 A：10 道「五选一」剔除题**——每题摆 5 件不同叶子的具体事，问「哪件最吃力」，
  被选中的叶子直接出局。
- 阶段 B / C：每叶两道行为题，选项 A→E 递增，档位 `[-7,-5,-3,-1,+1]`，跑分 ≤3 出局。
- 阶段 D：一道预测题。
- 目标是「~32 题固定流程」。

### 为什么弃用

1. **阶段 A 的五选一有隐性排序**。五个选项摆在一起，受测者会去猜「哪个是标准答案」，
   而「哪件最吃力」这种问法本身也在暗示强弱，污染了后面的行为题。
2. **每叶只出现一次**，一道题读错就永久误杀，没有第二次机会。
3. 单文件塞进 25 个变量 × 3 个阶段的题库和引擎后，已经不好维护；
   而且没有作答回收，无法验证题目好不好。

第二版（sf2.1）改成 **10 道情境二选一**、把引擎和题库拆成 ES 模块、接上 Node/SQLite 后台。
sf2.1 又被 sf2.2 取代：阶段 A 扩到 **25 道二选一**（每叶恰好出现两次、左右各一次、间隔 ≥7 题），
计分方向改成「扣未选的那个」。详见 [题库改版说明](题库改版说明.md)。

## 仍然成立的设计原则

以下几条从第一版沿用至今，没有变：

- **理念**：找出一件你自己平时可能没察觉到的强项。价值在「意外」——已知的强项再说一遍等于没说。
- **不设自评轨**。全程只答具体行为，受测者看不到候选清单、不给自己打分；
  唯一的自评是最后一道预测题，放在最后 → 零污染。
- **纯减法计分**：每叶起手 10 分，只有答出弱点才往下扣；没问到的叶子留在中点，不被误读成弱项。
- **结果必须引用受测者自己的回答**当证据——这是它和星座的唯一区别。
- 维度树固定：5 根 25 叶，每个叶尽量互斥（延续 1.0 `overview guide.txt` 的「不可组合还原」原则）。
- 25 个候选如何从 1.0 的 43 维收敛而来、「决策」这个根为什么差点没活下来——
  见 [新版升级说明](新版升级说明.md) 与 `README.md`。

## 1.0 完整面板（更早的版本）

`index.html`：131 题 → 42 个维度（0–100 分）→ 重新组合成 93 件具体的事，
输出面板、雷达图、RPG 式称号、场景排序。已冻结，不再维护，仍可从 `/index.html` 打开。

### 1.0 的存档约束（改它之前必看）

答案存档与「选择压缩码」都以**绝对题号**索引。纯内容编辑安全；
**新增／删除／换顺序整题**会让既有存档整体位移，必须同步递增 `index.html` 里的
`const KEY` 与 `const CODE_VER`。本轮没有改 `index.html`。

后台（`server/`）最初是围绕 1.0 的四区块结构建的，那部分（`routes/audit.js` 等）
在 2.0 下有一半概念失效，判读见 [准确率方法论](準確率方法論.md)。
